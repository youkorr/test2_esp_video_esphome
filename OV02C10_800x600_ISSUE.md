# OV02C10 Format 800x600 : Watchdog Timeout Issue

## ❌ Problème Identifié

La résolution **800x600 @ 30fps** cause un **watchdog timeout** après exactement 60 secondes, provoquant un reboot de l'ESP32-P4.

### 🔍 Symptômes

```
[22:02:59][I][esp_cam_sensor:1205]: ✓ Streaming started
[22:03:59]E (151237) task_wdt: Task watchdog got triggered. The following tasks/users did not reset the watchdog in time:
[22:03:59]E (151237) task_wdt:  - loopTask (CPU 1)
[22:03:59]E (151237) task_wdt: Aborting.
```

**Timing** : Le crash arrive **exactement 60 secondes** après le démarrage du streaming.

### 📊 Analyse Technique

#### 1. Configuration Capteur : ✅ OK

Les registres OV02C10 pour 800x600 sont **identiques** à ceux des autres formats fonctionnels :

| Format | Width | Height | HTS | VTS | Crop Window |
|--------|-------|--------|-----|-----|-------------|
| 640x480 ✅ | 640 | 480 | 2280 | 1164 | 0-1935 x 4-1091 |
| **800x600 ❌** | **800** | **600** | **2280** | **1164** | **0-1935 x 4-1091** |
| 1288x728 ✅ | 1288 | 728 | 2280 | 1164 | 0-1935 x 4-1091 |
| 1920x1080 ✅ | 1920 | 1080 | 2280 | 1164 | 0-1935 x 4-1091 |

**Conclusion** : Les registres du capteur sont corrects. Le problème n'est **pas** dans le capteur.

#### 2. Allocation Mémoire : ✅ OK

```
[22:02:59][I][esp_cam_sensor:1076]: Format: 800x600 RGB565, buffer size: 960000 bytes (937 KB)
[22:02:59][I][esp_cam_sensor:1090]:   Buffers: 3 × 960000 bytes = 2812 KB total
[22:02:59][I][esp_cam_sensor:1117]:   ✓ Buffer[0]: 0x483d7740 (aligned to 64 bytes)
[22:02:59][I][esp_cam_sensor:1117]:   ✓ Buffer[1]: 0x484c1d80 (aligned to 64 bytes)
[22:02:59][I][esp_cam_sensor:1117]:   ✓ Buffer[2]: 0x485ac3c0 (aligned to 64 bytes)
```

**Calcul** : 800 × 600 × 2 (RGB565) = 960 000 bytes ✅

**Conclusion** : Les buffers sont alloués correctement en SPIRAM avec bon alignement.

#### 3. Pipeline ISP/PPA : ❌ PROBLÈME

Le streaming démarre mais **aucune frame n'est produite** :

```
[22:02:59][I][esp_cam_sensor:1205]: mipi_dsi_cam: streaming started
[22:02:59][I][esp_cam_sensor:1245]: ✓ ov02c10: Using sensor built-in AWB
```

Puis **timeout watchdog** après 60 secondes → le code ESPHome attend une frame qui ne vient jamais.

**Hypothèse** : L'ISP ESP32-P4 ou le PPA (Pixel Processing Accelerator) **ne peut pas traiter** la résolution 800x600.

Possibles causes :
1. **Limitation ISP** : L'ISP ne supporte peut-être pas le downscaling 1936x1088 → 800x600
2. **Bug PPA** : Le PPA peut avoir un bug spécifique à cette résolution
3. **Deadlock** : Problème de synchronisation dans le pipeline ISP→PPA→Buffer

### 🔬 Comparaison avec Formats Fonctionnels

| Format | Status | Ratio | Downscaling | Notes |
|--------|--------|-------|-------------|-------|
| 640x480 | ✅ Fonctionne | 4:3 (1.33) | 1936→640 (33%), 1088→480 (44%) | OK |
| **800x600** | **❌ Crash** | **4:3 (1.33)** | **1936→800 (41%), 1088→600 (55%)** | **Watchdog timeout** |
| 1288x728 | ✅ Fonctionne | 16:9 (1.77) | 1936→1288 (67%), 1088→728 (67%) | OK |
| 1920x1080 | ✅ Fonctionne | 16:9 (1.78) | Native (pas de downscaling) | OK |

**Observations** :
- 640x480 et 800x600 ont le **même ratio** (4:3) mais 800x600 crash
- 1288x728 fonctionne avec un downscaling de **67%**
- 800x600 a un downscaling de **41-55%** qui semble problématique

**Hypothèse** : Peut-être que l'ISP a des **paliers de downscaling spécifiques** supportés (33%, 67%, 100%) et 41-55% ne fonctionne pas.

## ✅ Solutions de Contournement

### Option 1 : Utiliser 640x480 (Recommandé pour 4:3)

```yaml
esp_cam_sensor:
  resolution: "640x480"    # ✅ Fonctionne, ratio 4:3
  pixel_format: "RGB565"
  framerate: 30
```

**Avantages** :
- Même ratio 4:3 que 800x600
- Résolution VGA standard
- Stable, pas de crash

**Inconvénients** :
- Résolution plus basse (640×480 vs 800×600)

### Option 2 : Utiliser 1288x728 (Recommandé pour 16:9)

```yaml
esp_cam_sensor:
  resolution: "1288x728"   # ✅ Fonctionne, ratio 16:9
  pixel_format: "RGB565"
  framerate: 30
```

**Avantages** :
- Haute résolution (1288×728)
- Ratio 16:9 moderne
- Stable, 30 FPS

**Inconvénients** :
- Ratio différent de 800x600 (16:9 vs 4:3)
- Consomme plus de bande passante

### Option 3 : Utiliser 1920x1080 (Full HD)

```yaml
esp_cam_sensor:
  resolution: "1920x1080"  # ✅ Fonctionne, Full HD
  pixel_format: "RGB565"
  framerate: 30
```

**Avantages** :
- Résolution maximale (Full HD)
- Ratio 16:9
- Pas de downscaling ISP (native sensor)

**Inconvénients** :
- Très haute bande passante
- Plus de SPIRAM utilisé

```yaml
  ppa_enabled: false       # Désactiver PPA
```

